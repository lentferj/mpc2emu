# ACCEPTED VIOLATIONS IN PUBLISHED COMMIT MESSAGES.
#
# The project rule is that no commercial library, vendor, volume or preset
# name appears in a tracked file or a commit message (see §RELSCAN). A tracked
# FILE can be edited, so a hit in one is always a defect to fix and is never
# listed here. A pushed MESSAGE cannot be edited without rewriting every sha
# after it, which invalidates every clone and reference; so where the cost of
# the rewrite is judged worse than the exposure, the commit is named here
# instead of being silently tolerated.
#
# ⚠ THIS FILE IS TRACKED, SO IT MAY NOT CONTAIN A SINGLE COMMERCIAL NAME.
# That is why each line is a sha and a COUNT and nothing else: the count says
# how many term hits were read and accepted in that message. A bare "ignore
# this commit" would also hide a DIFFERENT name landing in the same message
# later. If the count stops matching in either direction the scan REFUSES --
# an exception nobody re-read is a standing permission, not a record.
#
# Format:  <40-char sha> <accepted hit count>   # short note, no names
#
# Adding a line is a decision, not maintenance. It needs Jan's call, and the
# reason belongs in docs/RESOLUTION_NOTES.md §RELSCAN.
